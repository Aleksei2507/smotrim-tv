# Проверка переходов без Android-плеера

`index.html` и `fixture.js` подменяют только Android-мост. Интерфейс загружается из текущих производственных assets. Видео, торренты и YouTube не запускаются. Кнопка сверху моделирует ошибку источника; остановка посылает `position` и `stopped` асинхронно, как Android.

Для локального предпросмотра скопируйте эти два файла в отдельную папку и добавьте ссылки `ui`, `movies.json`, `preview-channels.json` на одноимённые объекты из `app/src/main/assets`. Запустите в этой папке `python3 -m http.server 8767 --bind 127.0.0.1`. Не запускайте сервер в корне проекта с ключами подписи.

Сценарии для обычных действий через интерфейс:

1. Главная → «Смотреть»: сразу список источников. «О фильме» открывает карточку.
2. Открыть тестовую раздачу, выйти кнопкой «Назад», затем запустить её через «Продолжить просмотр» на главной. «Другой вариант» в плеере возвращает список того же фильма. «Назад» из списка возвращает на главную.
3. Повторить после кнопки «ТЕСТ: ошибка воспроизведения»: «Смотреть» открывает список, не главную.
4. Найти шоу по произвольному запросу, открыть раздачу, выйти. Продолжить её с главной, нажать «Другой вариант»: восстанавливается исходный поисковый запрос.
5. На телеканалах открыть поиск: тестовый мост отвечает «Пятница». Результаты остаются в общем списке; стрелка вправо ведёт к просмотру и избранному.

Файлы этой папки не входят в Android assets и в release APK.


## Проверка языка 0.5.2

`language.html` и `language-fixture.js` — изолированный стенд без внешних запросов и воспроизведения. Скопируйте их в отдельную папку вместе с актуальной папкой `ui` из Android assets; запускайте HTTP-сервер только на 127.0.0.1, отдельный порт. Не публикуйте папку проекта с ключом подписи через HTTP.

Поиск → системная клавиатура возвращает тестовый запрос «ДЮНА ПРОРОЧЕСТВО». Откройте карточку и серию 3: сверху виден переданный native-мосту запрос. Проверьте русский сборник выше английской отдельной серии, неизвестный язык SuccessfulCrab и смену предпочтения RUS/ENG. Смена языка должна сразу менять и подписи, и порядок выбираемых строк. На карточке есть пояснение об английских описаниях и кнопка настройки каталогов; «Готово» возвращает фокус к ней. Повторите при очень крупном тексте.

## Проверка интерфейса 0.2.4

`ux.html` и `ux-fixture.js` — отдельный стенд с 12 вариантами просмотра, длинными названиями, каналами, пустыми результатами и ошибками. Для него нужны ссылки `ui` и `movies.json` на производственные assets, а `artwork` — на `app/src/main/assets/ui/artwork`. Размещайте всё в отдельной папке без ключей и других файлов проекта; запускайте HTTP-сервер только на 127.0.0.1. Красная панель переключает ответы тестового моста, не внешние сервисы.

Проверяйте сценарии из раздела 0.2.4 в TESTING.md. У каретки все позиции имеют постоянную ширину; при перемещении проверяйте неизменность координат `.query-letter`. Для длинной строки допускается прокрутка поля, чтобы каретка оставалась видимой. Тестовый стенд хранит собственную историю в origin своего порта; не используйте его вместо пользовательского APK.


## Проверка функций 0.3.0

`playback.html` и `playback-fixture.js` проверяют серии, историю, программу передач, таймер, перемотку и порядок каналов. Скопируйте оба файла в отдельную папку и добавьте ссылки `ui`, `movies.json` и `artwork` как для ux.html. Запускайте HTTP-сервер на отдельном порту, например 8768, только на 127.0.0.1. Красная панель моделирует конец видео, CH+ и возврат на предыдущий канал. Настоящий плеер и установка APK здесь не запускаются.

Проверьте выбор сезона, запуск серии, перемотку с подтверждением OK, продолжение после перезагрузки, следующую серию, одну карточку сериала и отметку просмотренного в истории. Для порядка каналов: OK — взять, ↑↓ — одна позиция, ←→ — десять; OK закрепляет, «Назад» отменяет текущий перенос, «Сохранить порядок» сохраняет весь список. Отдельно проверьте отмену редактора и порядок избранных, открыв его из фильтра «Избранные».

Чистые функции без браузера: `node --test ui-tests/features.test.cjs`. Это дополняет, но не заменяет проверки фокуса через интерфейс и Android-тесты настоящего плеера.


## Проверка функций 0.4.0

`series.html` и `series-fixture.js` — изолированный стенд карточек сериалов и читаемости. Скопируйте оба файла в отдельную папку со ссылками `ui`, `movies.json`, `artwork`, как выше. Запускайте только на 127.0.0.1, отдельный порт (например 8769). Сеть каталога, голос, торрент и видео имитируются.

- Поиск в режиме «Сериалы», голос/системная клавиатура, пустые результаты, ошибка и повтор.
- Сезоны 0–12, длинные названия, будущие серии, отметка просмотра стрелкой вправо.
- S1E1 → S1E2 автоматически из раздачи; S1E3 отсутствует — поиск другой раздачи и ручной выбор файла. S2E1 не подставляется вместо S1E3.
- Выход и продолжение, в том числе после перезагрузки и смены magnet: позиция сохраняется для той же серии.
- Назад из вариантов возвращает к выбранной серии. При прокрутке фокус остаётся видимым.
- Три размера текста, контрастная рамка, уменьшенные анимации. Проверить карточку сериала, поиск, главную, плеер и настройки при 1280×720.

`node --test ui-tests/*.test.cjs`. Нативная проверка выбора файла и позиции: `SeriesPlaybackTest`; сетевой торрент с локальной раздачей: `AndroidPlaybackTest`.


## Проверка буфера 0.4.1

На стенде series.html откройте раздачу и выберите файл, затем нажмите тестовую кнопку «Кэш заполнен». Она моделирует 128 / 128 МБ кэша, одно подключение, 0,3 МБ/с и нулевой запас видео. В центре должно быть «Подгружаем следующий фрагмент…» и «Запас: 0 сек». «Ещё → Загрузка и буфер» показывает кэш отдельно и объясняет ожидание. Это имитация статуса; сетевой поток на стенде не запускается.

В настройках проверьте пять вариантов буфера и кнопку «Назад» при очень крупном тексте. «Память и сбои» использует тестовые данные, включая искусственную причину завершения; это не диагностика устройства, на котором открыт браузер.

PlaybackMemoryTest проверяет лимит загрузки Media3 по байтам, паузу до готовности плеера и восстановление MainActivity после настоящего искусственно вызванного сбоя WebView. AndroidPlaybackTest декодирует локальный торрент с буферами 64, 96 и 256 МБ и производственной настройкой Media3.


## Проверка часов и хранения буфера 0.5.3

На изолированном стенде `playback.html` откройте любой тестовый канал или файл. Кнопка «Часы +2 мин» меняет время только стенда: часы плеера должны обновиться в течение секунды без перерисовки и сброса фокуса. Повторить со скрытой панелью и после возврата управления.

В «Настройки → Буфер видео» переключите место хранения, выберите 512 МБ или 1 ГБ. Проверить возврат фокуса к строке настройки, сохранённую подпись, отмену переключения через «Назад», оба набора размеров и прокрутку до «Назад» при очень крупном тексте. Стенд имитирует сохранение: реальные SharedPreferences проверяются в APK.

`TorrentStreamingTest` использует настоящий TorrServer и локальный Java-пир BEP 3 без JNI. Для RAM и диска: 64-МиБ тестовый файл, 24-МиБ кэш (движок удерживает до 16 МиБ начала/конца сверх окна чтения), чтение с проверкой байтов, перемотка, ограниченный объём на диске, удаление после закрытия и повторный запуск с чтением возле конца файла без полной повторной загрузки. `TorrentBufferPolicyTest` проверяет резерв свободного места и независимость Go RAM от размера дискового кэша.

## GitHub-каталог

`github.html` и `github-fixture.js` используют настоящие файлы `catalog/v1` через тестовый мост, без подключения торрента. В отдельной папке нужны ссылки `ui` и `catalog` на производственные assets. Проверить: «Смотреть» на главной → «Выберите качество» → передача варианта плееру; «Найти другие варианты» → один искусственный результат и счётчик ручных запросов; сериал → сезон → серия → готовые варианты; возврат, пагинация и настройки каталога. После пересборки JSON перезагрузить страницу, чтобы стенд получил новый индекс.
